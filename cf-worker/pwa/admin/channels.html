推送渠道

审批请求会推送到此处启用并配置的所有渠道——两个渠道相互独立，可只用其一，也可同时启用。每个卡片右上角的开关控制是否启用，启用后展开填写。本页只在浏览器内生成 JSON：填好字段点「生成」，再把结果 wrangler secret put 成对应的环境变量。现有 secret 的明文不会回显到本页。

Slack

{{SLACK_BADGE}}
{{SLACK_KEEP_NOTE}}

⚠️ Slack 走 Incoming Webhook，是单向通知：不支持审批通过/拒绝后回改原消息，也不 @ 人。审批结果只会在审批页与审计页更新。需要「@相关人 + 决策后回改消息」请用下方的 Slack App（Bot token）或飞书 / Lark 通道。

用 Incoming Webhook 方式——这是单向通知（真正的「同意」仍在审批页用 Passkey 完成），所以只需一个 Webhook URL，无需 bot、无需把机器人拉进频道：

  1. 打开 api.slack.com/apps → Create New App → From scratch，填个名字（如 vt-approval）并选择目标 workspace。
  2. 左侧 Incoming Webhooks → 打开 Activate Incoming Webhooks 开关。
  3. 页面底部 Add New Webhook to Workspace → 选择接收审批通知的频道（如 #vt-approvals）→ Allow。
  4. 复制生成的 Webhook URL（形如 https://hooks.slack.com/services/T…/B…/…），粘贴到下方。

所需「权限」就是激活 Incoming Webhooks 时自动添加的 incoming-webhook scope，仅能向你授权的那个频道发消息，无其它权限。换频道就重做第 3 步再换 URL 即可。

Slack App

{{SLACKAPP_BADGE}}
{{SLACKAPP_KEEP_NOTE}}

用自建应用（Bot token）方式——这是 Slack 侧唯一能@相关人并在审批后回改原消息填结果的通道（上面的 Incoming Webhook 做不到）。完整步骤见 docs/slack-app.md：创建 App → 加 Bot Token Scopes（chat:write，如按频道名发送另加 chat:write.public）→ 安装到 workspace 取 Bot User OAuth Token（xoxb-…）→ 把 Bot 拉进目标频道 → 取频道 ID（C…）与要 @ 的人的成员 ID（U…）。

免审批（缓存命中）通知会精简为一两行、不 @ 任何人；审批请求才会 @ 上面列出的人，并带「去审批」按钮。

飞书 / Lark

{{FEISHU_BADGE}}
{{FEISHU_KEEP_NOTE}}

用自建应用（机器人）方式——这是唯一能@相关人并在审批后回改原卡片填结果的通道（飞书自定义机器人 webhook 做不到）。完整步骤见 docs/feishu.md：创建自建应用 → 开启机器人 → 授予 im:message / im:message:send_as_bot → 发布 → 把机器人拉进目标群 → 取 chat_id 与要 @ 的人的 open_id。

免审批（缓存命中）通知会精简为一两行、不 @ 任何人；审批请求才会 @ 上面列出的人，并带「去审批」按钮。
