推送渠道

审批请求会推送到此处启用并配置的所有渠道——两个渠道相互独立，可只用其一，也可同时启用。每个卡片右上角的开关控制是否启用，启用后展开填写。本页只在浏览器内生成 JSON：填好字段点「生成」，再把结果 wrangler secret put 成对应的环境变量。现有 secret 的明文不会回显到本页。

Pushover

{{PUSHOVER_BADGE}}
{{PUSHOVER_KEEP_NOTE}}

在 pushover.net 登录后：① 主页顶部的 Your User Key 即 user_key；② 在 Create an Application/API Token 新建一个应用，拿到 API Token 作为 app_token。手机装 Pushover App 并登录同一账号即可收推送。

Slack App

{{SLACKAPP_BADGE}}
{{SLACKAPP_KEEP_NOTE}}

用自建应用（Bot token）方式——Slack 侧能@相关人并在审批后回改原消息填结果的通道。完整步骤见 docs/slack-app.md：创建 App → 加 Bot Token Scopes（chat:write，如按频道名发送另加 chat:write.public）→ 安装到 workspace 取 Bot User OAuth Token（xoxb-…）→ 把 Bot 拉进目标频道 → 取频道 ID（C…）与要 @ 的人的成员 ID（U…）。

免审批（缓存命中）通知会精简为一两行、不 @ 任何人；审批请求才会 @ 上面列出的人，并带「去审批」按钮。

飞书 / Lark

{{FEISHU_BADGE}}
{{FEISHU_KEEP_NOTE}}

用自建应用（机器人）方式——这是唯一能@相关人并在审批后回改原卡片填结果的通道（飞书自定义机器人 webhook 做不到）。完整步骤见 docs/feishu.md：创建自建应用 → 开启机器人 → 授予 im:message / im:message:send_as_bot → 发布 → 把机器人拉进目标群 → 取 chat_id 与要 @ 的人的 open_id。

免审批（缓存命中）通知会精简为一两行、不 @ 任何人；审批请求才会 @ 上面列出的人，并带「去审批」按钮。
